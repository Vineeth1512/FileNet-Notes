🟦 ⭐ QUEUE — COMPLETE EXPLANATION (IBM FILENET PROCESS ENGINE)


---

1️⃣ TECHNICAL DEFINITION

A Queue in IBM FileNet Process Engine is a container that holds work items waiting to be processed by users, groups, or systems.

Each workflow step outputs a work item into a queue.
Users or systems read the queue and complete those work items.


---

2️⃣ REAL-LIFE DEFINITION

A Queue is like a tray or inbox where pending tasks are placed for people to pick up and complete.

Example:

A tray in HR office with all pending forms

Ticket counter queue

Support team inbox holding all customer issues


Queue = A place where work waits until someone handles it.


---

3️⃣ WHAT IT IS (Simple Explanation)

A Queue:

Stores work items generated by workflows

Assigns work to users or groups

Controls how tasks move from one user to another

Determines who is responsible for the next step

Supports parallel and conditional routing


Whenever a workflow reaches a step that needs manual/system processing,
it goes to a Queue.

Users open IBM Navigator / Workplace XT → see items in their queue.


---

4️⃣ WHY WE USE QUEUES (Purpose)

✔ To assign work to users or teams

Workflow places tasks into appropriate queues.

✔ To distribute tasks load-wise

Multiple users can share the same queue.

✔ To manage workflow routing

Based on rules, items go to different queues.

✔ To enable monitoring

Supervisors can see items in their team queue.

✔ To support parallel processing

Multiple users can pick different items from the same queue.

✔ To separate responsibilities

HR queue vs Finance queue vs Manager queue.


---

5️⃣ TYPES OF QUEUES IN PROCESS ENGINE

1️⃣ User Queue

Tasks assigned to a specific user.

Example:

Queue of user “Vineeth”


2️⃣ Group Queue

Tasks assigned to a group of users.

Example:

HR Team queue

Finance Approver queue

Manager Review queue


Anyone in the group can pick the work.

3️⃣ System Queue

Used for automated processing.

Example:

Component Queue

Timeout Queue

Event Action Queue


System queues run code, actions, or automatic steps.

4️⃣ Roster Queue (Not actual queue but related)

Roster tracks workflow instance but is not a task queue.


---

6️⃣ WHAT IS THIS IN REAL LIFE?

📌 Real-Life Analogy: Office Inbox Tray

In an office:

All incoming files are placed in an "INBOX" tray

Staff pick one file at a time

After completing, they put it in "OUTBOX" tray


This is exactly how workflow queues work.

Queue = INBOX tray
Work item = File kept in tray
User = Person picking the file


---

7️⃣ MATCHING FILENET EXAMPLE (Real-Time Scenario)

⭐ Workflow: Invoice Approval Workflow

When an invoice is uploaded:

Step 1: Verification Step

Work item goes to Finance_Verification_Queue

Finance user picks it

Verifies invoice

Completes step


Step 2: Manager Approval

Work item moves to Manager_Approval_Queue

Any manager in the group can pick

Approves or rejects


Step 3: Archive Step (System Step)

Work item moves to System_Archive_Queue

A code module or automated step archives the document


THIS IS HOW QUEUES MOVE WORK THROUGH A WORKFLOW.


---

8️⃣ QUEUE VS ROSTER VS INBOX

Concept	Definition	Usage

Queue	Holds work items waiting for action	Assign tasks to user/group
Roster	Stores metadata of workflow instances	Search, audit, reporting
Inbox	User’s personal view of queue items	User sees only their tasks



---

9️⃣ KEY FIELDS IN QUEUE ITEMS (Work Items)

Work item in a queue contains:

Workflow number

Step name

Assigned user/group

Deadline

Lock status

Data fields (LoanID, Amount, Status…)

Instructions
